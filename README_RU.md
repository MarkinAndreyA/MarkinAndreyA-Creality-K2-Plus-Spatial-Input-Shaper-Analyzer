# K2 Spatial Analyzer — руководство пользователя

**Обычная редакция · V1.0.0 · 23.09.2026**

Пошаговая инструкция для обычного пользователя: от первого запуска до отчёта.

[English](README_EN.md) · [Advanced RU](README_ADVANCED_RU.md) · [Advanced EN](README_ADVANCED_EN.md)

## Как пользоваться этим руководством

Обычная редакция рассчитана на пользователя, которому нужно запустить готовый Windows-пакет, проанализировать Measurement, получить рекомендации и отчёт, не погружаясь в архитектуру приложения. Опасные или редко используемые функции отмечены отдельно.

> **Важно:** «Обычная» и «Advanced» — это две редакции документации, а не два режима приложения. Интерфейс K2 Spatial Analyzer один и тот же.

## Что умеет K2 Spatial Analyzer

- принимать Spatial Measurement как архив TAR/TAR.GZ/TGZ/ZIP или как папку с RAW-данными;
- рассчитывать рекомендации Input Shaper и общий рекомендуемый `max_accel` по доступным AX/AY измерениям;
- использовать несколько расчётных движков: `K2_NATIVE_EXACT`, `cleanroom_upstream_2026` и `UPSTREAM_EXACT`;
- опционально ускорять RAW Welch FFT/PSD через CuPy/CUDA; при недоступности CUDA анализ может работать на CPU;
- строить HTML/PDF/PNG-отчёты и сравнительный анализ COLD / LOW_TEMP / HIGH_TEMP;
- проводить Measurement/Belt Gate и пространственный сбор RAW на K2 Plus;
- записывать рассчитанный K2_NATIVE Input Shaper на K2 Plus через отдельную защищённую транзакцию.

> **Безопасность:** анализ сохранённых данных и формирование отчётов не требуют движения принтера. Measurement может нагревать и перемещать принтер. Запись Input Shaper изменяет `printer.cfg` и runtime-настройки. Эти действия выполняйте только осознанно и при отсутствии активной печати.

## Установка и первый запуск

### Portable или MSI

| Вариант | Когда выбирать | Где хранятся рабочие данные |
|---|---|---|
| Portable | Нужно запускать без установки, переносить папку целиком, тестировать новую версию | В подпапке `runtime` рядом с `K2SpatialAnalyzer.exe` |
| MSI | Нужна обычная системная установка и ярлык в меню Пуск | `%LOCALAPPDATA%\FDM_AI_Lab\K2_Spatial_Analyzer\runtime` |

> **CUDA и путь:** для Portable с CUDA используйте путь только из ASCII-символов, например `D:\K2Spatial\K2_Spatial_Analyzer\`. Не распаковывайте CUDA-версию в каталог с кириллицей в полном пути.

1. Portable: распакуйте архив в отдельную папку с коротким ASCII-путём. MSI: запустите установщик и завершите обычную установку Windows.
2. Запустите `K2SpatialAnalyzer.exe` или ярлык «K2 Spatial Analyzer».
3. Внизу окна выберите «Русский» или English. Переключение языка выполняется без перезапуска приложения.
4. Для первого знакомства не подключайте принтер: сначала выполните анализ готового Measurement.

## Быстрый старт: анализ готового Measurement

> **Рекомендуемый первый сценарий:** если у вас уже есть Measurement, начните именно с него. Это полностью отделяет изучение Analyzer от live-управления принтером.

1. Откройте вкладку «Анализ».
2. Выберите тип источника: «Архив TAR/TAR.GZ/ZIP» либо «Папка отчёта Spatial».
3. Нажмите «Обзор…» и выберите Measurement. Для папки внутри неё должна существовать RAW либо вложенная папка, содержащая RAW.
4. В блоке «Расчётные движки» для первого запуска оставьте `cleanroom_upstream_2026`. `K2_NATIVE_EXACT` и `UPSTREAM_EXACT` включайте только если соответствующие исходники уже доступны.
5. Оставьте CPU workers = 0 (Auto). Если у вас поддерживаемая NVIDIA/CuPy среда, включите «CUDA RAW FFT (CuPy)» и дождитесь проверки CUDA.
6. Не меняйте SCV, hard max_accel, zoning и другие численные параметры, пока не освоите базовый маршрут.
7. Нажмите «Проверить входные данные». После PASS нажмите «Запустить анализ».
8. Во время расчёта приложение откроет вкладку «Журнал». После успешного численного анализа автоматически формируются статические PNG и обновляется отчёт.
9. Перейдите на вкладку «Результаты», проверьте рекомендации и сформируйте PDF при необходимости.

> **Частичный dataset:** набор не обязан содержать полный стандартный объём измерений. Analyzer работает по фактически доступным AX/AY точкам; общий `max_accel` выводится только если присутствуют обе основные оси.

## Как читать вкладку «Результаты»

| Поле | Что означает для пользователя |
|---|---|
| Input Shaper X / Y | Рекомендуемый тип shaper и частота для соответствующей оси |
| Worst X / Y, % | Worst-метрика выбранного результата по оси. Чем ниже, тем лучше в рамках сравниваемого результата |
| Smoothing X / Y @ 5000 | Сравнительная reference-точка FDM AI Lab при 5000 мм/с². Это не «стандарт Klipper» |
| Предел X / Y | Рассчитанный предел ускорения по каждой оси |
| Ограничение | Показывает, какая ось/условие ограничивает общий результат |
| Result Worst / smoothing / residual vibration | Метрики уже выбранного результата. Result smoothing пересчитывается для общего рекомендуемого `max_accel` |
| Рекомендуемый max_accel | Общий рекомендуемый предел для результата, когда доступны обе основные оси |

### HTML, PDF и PNG

- «Открыть HTML-отчёт» — удобный интерактивный/экранный просмотр результата.
- «Сформировать PDF» — создаёт PDF на текущем выбранном языке интерфейса.
- «Экспорт PNG» — формирует статические графики. Предпросмотр поддерживает масштаб 5–400% и «По размеру окна».
- «Обновить из результата» — синхронизирует effective-state, summary и REPORT; актуальные PNG не пересчитываются без необходимости.

## CUDA: что включать и как понять, что всё работает

CUDA в V1.0.0 ускоряет только RAW Welch FFT/PSD preprocessing. Exact-engine fitting, Plotly и Matplotlib/PDF этим переключателем не ускоряются.

Успешный CUDA-маршрут содержит:

```text
CUDA_REQUESTED=1
CUDA_ACTIVE=1
CUDA_BACKEND=CUPY_ACTIVE:<GPU>
ANALYZER_STATUS=PASS
```

> **Предупреждение CUDA_PATH:** сообщение «CUDA path could not be detected» само по себе не означает ошибку. Если далее указано `CUDA_ACTIVE=1` и `ANALYZER_STATUS=PASS`, CuPy backend фактически работает.

## Сравнение COLD / LOW_TEMP / HIGH_TEMP

1. Откройте «Сравнение профилей». Для каждого профиля есть отдельные кнопки «Архив…» и «Папка…».
2. Выберите минимум два разных источника. Один и тот же source нельзя назначить сразу двум профилям.
3. Если metadata явно доказывает профиль, приложение не позволит подать LOW_TEMP как COLD или HIGH_TEMP.
4. Если старый dataset не содержит доказуемого profile provenance, приложение покажет предупреждение и предложит продолжить как legacy/unknown без угадывания.
5. Нажмите «Запустить сравнение профилей». После PASS можно открыть сравнительный HTML или сформировать PDF.

**Что сравнивается:** совпадающие XYZ/axis точки, изменения Input Shaper, residual, max_accel и Practical Print Envelopes. Температурный slope в сравнении маркируется как observational, а не как доказательство причинности.

## Measurement на реальном K2 Plus

> **Не начинайте с этого сценария.** Сначала убедитесь, что анализ сохранённого Measurement работает. Live Measurement включает thermal/belt/stress gate и физические перемещения принтера.

1. На вкладке «Измерения» укажите IP/hostname принтера и нажмите «Тест связи».
2. Выберите профиль: COLD, LOW_TEMP или HIGH_TEMP.
3. Для первого ознакомления оставьте сетку 3×3×3 и сначала нажмите «Сформировать план без принтера». Это позволяет проверить план без live-действий.
4. Перед live-запуском убедитесь, что печать не идёт, рабочая зона свободна и принтер исправен.
5. Нажмите «Запустить обязательный Measurement Gate». Gate проверяет температурный режим, belt model/repeatability и выполняет stress-последовательность.
6. После PASS Gate можно запустить Spatial acquisition кнопкой «Запустить Input Shaper после PASS». Если включён автоматический запуск, acquisition стартует после разрешающего Gate автоматически.
7. Готовый Measurement появится в `runtime\measurements` и затем может использоваться во вкладке «Анализ».

| Профиль | Температурный режим |
|---|---|
| COLD | Пассивный: сопло ≤35 °C, стол ≤35 °C, камера ≤35 °C |
| LOW_TEMP | Сопло 140 °C, стол 70 °C, камера 45 °C |
| HIGH_TEMP | Сопло 280 °C, стол 110 °C, камера 58 °C |

> **Нагрев:** если профиль уже достигнут, дополнительный 30-минутный hold не требуется. Если нет — приложение доводит профиль до целевых температур и затем выдерживает 1800 с. Нагрев после завершения автоматически не снимается.

## Запись Input Shaper на K2 Plus

> **Редко нужна новичку:** для изучения Analyzer эту функцию можно полностью не использовать. Она изменяет конфигурацию принтера.

- Запись доступна только из рассчитанных результатов `K2_NATIVE_EXACT`.
- X/AX и Y/AY выбираются независимо: Auto либо конкретный рассчитанный candidate.
- Перед изменением приложение читает текущий `printer.cfg` и блокирует запись при printing/paused или при неожиданном активном `[input_shaper]` в include-файле.
- Перед записью создаётся и проверяется backup `printer.cfg`; SAVE_CONFIG `[input_shaper]` очищается, старый основной блок комментируется, новый FDM AI Lab block записывается после него.
- Runtime применяется через `SET_INPUT_SHAPER` без `SAVE_CONFIG`, `CXSAVE_CONFIG` или restart.
- Финальное подтверждение по умолчанию — «Нет». Если вы не уверены, отмените операцию.

## Типовые проблемы

| Симптом | Что проверить |
|---|---|
| «Источник Spatial не найден» | Проверьте выбранный файл/папку и тип источника |
| «В выбранной папке не найдена RAW» | Выбрана не корневая Spatial-папка либо не тот каталог |
| K2_NATIVE_EXACT / UPSTREAM_EXACT не запускается | Нужен доступный каталог исходников соответствующего движка; иначе снимите галочку и используйте cleanroom |
| CUDA_PATH warning | Смотрите фактический `CUDA_ACTIVE`. При `CUDA_ACTIVE=1` это предупреждение не является отказом backend |
| Сравнение отклоняет source | Проверьте duplicate и provenance: LOW_TEMP нельзя назначать как COLD/HIGH_TEMP, один source — двум слотам |
| PDF не соответствует языку | Переключите язык GUI и сформируйте PDF заново |
| Ошибка операции | Откройте вкладку «Журнал», затем `runtime\logs`. Не удаляйте исходный Measurement до завершения диагностики |

## Короткий чек-лист перед публикацией issue в GitHub

- версия приложения и Portable/MSI;
- какой сценарий выполнялся: Analysis / Profile Comparison / Measurement / Write;
- последние нейтральные строки журнала без IP, usernames и локальных путей;
- `ANALYZER_STATUS` / `CUDA_ACTIVE` / `DATASET_STATUS` / `RAW_RECOGNIZED` / `ZONING_STATUS`, если применимо;
- не прикладывать credentials, private `printer.cfg` и несанифицированные Measurement/logs.

## Глоссарий

| Термин | Короткое объяснение |
|---|---|
| Measurement | Набор пространственных RAW-измерений вибраций и metadata |
| RAW | Исходные данные датчика для конкретной точки/оси |
| AX / AY | Основные измерительные оси X и Y |
| Input Shaper | Комбинация типа shaper и его частоты для подавления резонансов |
| SCV | Параметр square corner velocity, используемый расчётным контуром |
| Zoning | Построение зон/Practical Print Envelopes по выбранным порогам ускорения |
| Forced reevaluation | Переоценка уже рассчитанных candidate shapers без изменения baseline и без записи в `printer.cfg` |
| K2_NATIVE_EXACT | Контур, исполняющий фактические vendor-исходники K2 Plus |
| UPSTREAM_EXACT | Контур на фактическом pinned исходном коде Klipper |
| cleanroom_upstream_2026 | Независимая реализация современной математики Klipper для cross-check |
